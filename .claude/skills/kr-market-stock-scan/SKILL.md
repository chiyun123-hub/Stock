# 국내·해외 주식 스캔 오케스트레이터

## 실행 모드

**에이전트 팀**. 이 환경에는 `TeamCreate` 도구가 없지만, `Agent` 도구에 고정된 `name`을 지정해 background로 소환하면 그 이름으로 계속 살아있는 팀원이 되고, `SendMessage(to=이름, ...)`로 서로 직접 통신할 수 있다. 이 방식으로 팀을 구성한다.

- 오케스트레이터(메인)가 `domestic-stock-analyst`를 이름 `domestic`, `overseas-stock-analyst`를 이름 `overseas`로, 그리고 `market-report-writer`를 이름 `reportwriter`로 각각 `Agent(..., name=..., run_in_background=true, model="opus")` 소환한다.
- 세 에이전트는 소환 즉시 서로의 이름을 알고 있으며(에이전트 정의의 "팀 통신 프로토콜" 참조), 분석 중 교차 시장 신호를 발견하면 `domestic` ↔ `overseas`가 직접 `SendMessage`로 공유하고, 분석이 끝나면 각자 `reportwriter`에게 완료를 알린다.
- `TaskCreate`로 "국내 분석", "해외 분석", "리포트 종합" 3개 작업을 생성해 진행 상황을 추적하고, 각 에이전트가 완료 시 `TaskUpdate`로 상태를 갱신하게 한다.
- 오케스트레이터는 `reportwriter`가 `SendMessage(to="main", ...)`로 보내는 완료 알림을 받을 때까지 기다린다(백그라운드 알림으로 자동 수신).

## Phase 0: 컨텍스트 확인

1. `_workspace/` 디렉토리를 확인한다.
   - 오늘 날짜의 분석 파일이 이미 있고 사용자가 "다시/재실행/업데이트"를 요청 → **부분/전체 재실행**: 사용자가 "국내만" 또는 "해외만"이라고 특정하면 해당 분석 에이전트만 재호출하고, 다른 쪽은 기존 파일을 그대로 사용한다. 특정하지 않으면 둘 다 재호출한다.
   - 오늘 날짜 파일이 없음 → **초기 실행**: Phase 1부터 전체 진행.
2. 현재 시각이 한국 장 시간(평일 09:00~15:30 KST) 밖이면, 사용자에게 "현재는 장 운영 시간이 아니며, 가장 최근 거래일 기준 데이터로 분석합니다"라고 안내하고 계속 진행한다(작업을 막지 않음).
3. 사용자가 "장 열리는 시간마다" 처럼 반복 실행을 원하면, 이 스킬 자체는 1회 실행 로직만 담당하므로 `schedule` 스킬로 평일 장중 주기적 트리거(예: 매 시간 정각)를 별도로 설정하도록 안내한다. 하네스가 직접 크론을 구성하지는 않는다.

## Phase 1: 팀 소환 및 병렬 분석 실행

```
TaskCreate("국내 분석"), TaskCreate("해외 분석"), TaskCreate("리포트 종합")
Agent(domestic-stock-analyst, name="domestic", model="opus", run_in_background=true)
Agent(overseas-stock-analyst, name="overseas", model="opus", run_in_background=true)
Agent(market-report-writer, name="reportwriter", model="opus", run_in_background=true)
```

세 에이전트를 동시에 이름 지정 소환한다(리포트 작성자도 먼저 소환해 두어야 `domestic`/`overseas`가 완료 메시지를 보낼 대상이 존재한다). 각 분석 에이전트에게 오늘 날짜/현재 시각, 사용자가 지정한 관심 섹터(있다면), 그리고 팀원 이름(`domestic`/`overseas`/`reportwriter`)을 프롬프트에 포함해 전달한다. `reportwriter`에게는 `domestic`, `overseas`로부터 완료 메시지를 기다렸다가 작업을 시작하라고 전달한다.

두 분석가는 각자 `_workspace/{날짜}_{시간}_domestic_analysis.md`, `_workspace/{날짜}_{시간}_overseas_analysis.md`를 생성하고, 교차 신호는 서로에게 `SendMessage`로 공유하며, 완료 시 `reportwriter`에게 알린다(각 에이전트 정의의 "팀 통신 프로토콜" 참조).

## Phase 2: 기관 순매수 즉시 브리핑 (장중)

`domestic`은 본 스크리닝보다 먼저 이 브리핑을 처리하도록 소환 시 지시받는다(에이전트 정의의 "즉시 브리핑" 참조). 오케스트레이터는 이 결과를 본 분석 완료를 기다리지 않고 받는 즉시 사용자에게 전달한다.

1. 현재 시각이 한국 장 시간(평일 09:00~15:30 KST) 안이면, `domestic`이 KRX 투자자별 매매동향(기관 순매수 상위 종목)을 조회하고 그중 최근 1주일 누적 수익률이 가장 높은 3개 기업을 선정해 `_workspace/{날짜}_{시간}_domestic_institutional_top3.md`에 저장한다.
2. 장 시간 밖이면 `domestic`이 이 단계를 건너뛰고 그 사실만 `main`에게 알린다. 오케스트레이터는 사용자에게 "현재 장중이 아니라 기관 순매수 즉시 브리핑은 생략합니다"라고 안내한다.
3. `domestic`으로부터 `SendMessage`로 브리핑 결과(또는 생략 사유)가 도착하면, 오케스트레이터는 Phase 3(전체 분석) 완료를 기다리지 않고 **즉시** 사용자에게 요약(종목명·기관 순매수 규모·1주 수익률)을 전달한다. 이후 전체 상승/하락 10개 리포트는 계속 백그라운드에서 진행됨을 함께 안내한다.

## Phase 3: 결과 종합

`reportwriter`는 `domestic`, `overseas` 양쪽의 완료 메시지를 받은 뒤 스스로 판단해 두 분석 파일을 읽고 최종 리포트(`주식분석리포트_{날짜}_{시간}_new.md`)를 작성한다. `_workspace/`에 기관 순매수 즉시 브리핑 파일이 있으면 리포트에 "참고: 기관 순매수 Top3(장중 즉시 브리핑, 이미 전달됨)" 섹션으로 짧게 포함한다. 이어서 `stock-report-website` 스킬로 `site/data.json`을 갱신하고 웹페이지를 발행한다(채팅에 리포트 본문을 붙여넣지 않는다). 오케스트레이터는 별도로 호출하지 않고, `reportwriter`가 `SendMessage(to="main", ...)`로 보내는 완료 알림(사이트 링크 포함)을 기다린다.

## Phase 4: 정산 (장 마감 후 검증)

사용자가 "정산", "예측 정확도", "얼마나 맞았어" 등을 요청하거나, 이 스킬이 재트리거될 때 정산 대상 날짜가 있으면 이 Phase를 실행한다. Phase 0~3(오늘 분석)과 독립적으로 단독 실행 가능하다.

1. 정산할 날짜를 정한다(사용자가 특정하지 않으면 가장 최근 미정산 날짜). `site/data.json`에서 해당 날짜 항목을 확인한다.
2. 국내 정산은 국내 장 마감(15:30 KST) 이후에만, 해외 정산은 미국 장 마감 이후에만 유효하다. 아직 마감 전이면 그 사실을 안내하고 정산 가능한 시점을 알려준다(막지는 않되 무의미한 조회는 하지 않는다).
3. `domestic`을 이름 `domestic`으로(이미 살아있으면 재사용, 없으면 재소환) 불러 "국내 정산" 지시를 보낸다 — 에이전트 정의의 "정산 (장 마감 후 검증)" 절차를 따르게 한다.
4. 미국 장이 마감된 시점이면 `overseas`도 같은 방식으로 "해외 정산"을 지시한다.
5. 두 시장(또는 사용자가 요청한 한쪽)의 정산 완료 메시지를 받으면, `reportwriter`(또는 정산 전용으로 직접, 상황에 맞게)에게 `site/data.json`의 `accuracy` 필드를 재계산하고 `site/index.html`을 재생성해 기존 Artifact URL로 갱신 발행하도록 지시한다.
6. 사용자에게는 채팅에 전체 결과를 붙여넣지 않고, 적중률 요약(예: "8/12 적중률 65% (13/20), 사이트에서 종목별 차트 확인 가능")과 사이트 링크만 전달한다.

## 데이터 전달 프로토콜

- **메시지 기반**: `domestic` ↔ `overseas` 교차 신호 공유, `domestic`/`overseas` → `reportwriter` 완료 알림, `reportwriter` ↔ 분석가 확인 질의, `reportwriter` → `main` 최종 완료 알림. 모두 `SendMessage`로 실시간 처리한다.
- **태스크 기반**: `TaskCreate`/`TaskUpdate`로 "국내 분석", "해외 분석", "리포트 종합" 3개 작업의 진행 상태를 추적한다.
- **파일 기반**: 분석 에이전트 → `_workspace/*.md` → 리포트 작성 에이전트. 파일명 규칙: `{날짜}_{시간}_{domestic|overseas}_analysis.md`, 즉시 브리핑은 `{날짜}_{시간}_domestic_institutional_top3.md`. 대용량 분석 근거는 메시지가 아닌 파일로 전달한다.
- 최종 리포트만 프로젝트 루트에 출력하고, `_workspace/`의 중간 분석 파일은 감사 추적용으로 보존한다(삭제하지 않음).

## 에러 핸들링

- 한쪽 분석 에이전트가 실패(또는 일정 시간 내 `reportwriter`에게 완료 메시지를 보내지 못함)하면 오케스트레이터가 해당 이름으로 1회 재소환한다. 재실패 시 `reportwriter`에게 "해당 시장 분석 없이 진행"을 `SendMessage`로 지시하고, 성공한 쪽 데이터만으로 리포트를 작성하게 한다. 리포트 상단에 어느 시장 분석이 누락됐는지 명시한다.
- 두 분석 모두 실패하면 사용자에게 실패 사유(예: 데이터 소스 접근 불가)를 알리고 재시도 여부를 확인한다.
- `reportwriter`가 분석가에게 확인 질의를 보냈는데 일정 시간 응답이 없으면, 해당 항목을 "확인 불가"로 표기하고 리포트 작성을 계속 진행한다(무한 대기 금지).
- 상충 신호(국내/해외 분석 간 모순은 발생하지 않지만, 종목 자체 내 시세/뉴스 모순)는 삭제하지 않고 리포트에 별도 표기한다.
- 기관 순매수 즉시 브리핑 조회가 실패하면 `domestic`이 1회 재시도 후 실패 사유를 `main`에게 알리고 생략한다. 본 스크리닝(Phase 3)은 이 실패와 무관하게 정상 진행한다.

## 최종 안내 (필수)

리포트 본문을 채팅에 붙여넣지 않는다. `reportwriter`가 전달한 사이트 링크와 오늘 핵심 이슈 1~2개만 사용자에게 전달하고, 다음을 함께 전한다:
- 이 결과는 투자 자문이 아닌 참고용 스크리닝이라는 점
- 후보 종목 수가 각 10개에 못 미치면 그 사유
- 나머지 상세 내용(상승/하락 후보 전체, 날짜별 이력)은 사이트에서 확인하라는 안내

## 테스트 시나리오

**정상 흐름**: "오늘 국내랑 해외 주식 분석해서 오를 것 같은 거, 떨어질 것 같은 거 10개씩 알려줘" (장중 요청) → Phase 0(초기 실행 판별) → Phase 1(팀 소환, `domestic`/`overseas`/`reportwriter` 병렬 소환) → Phase 2(`domestic`이 기관 순매수 Top3 즉시 브리핑을 먼저 처리해 `main`에게 전달 → 오케스트레이터가 본 분석을 기다리지 않고 사용자에게 바로 요약 전달) → 이어서 본 스크리닝 진행 중 `domestic`↔`overseas` 필요시 교차 신호 공유 → 완료 시 각자 `reportwriter`에게 알림 → Phase 3(`reportwriter`가 종합, 필요 시 분석가에게 확인 질의) → `reportwriter`가 `main`에게 완료 알림 → 면책 문구 포함 리포트 전달.

**즉시 브리핑 흐름**: 장중에 "주식 분석해줘" 요청 → Phase 2에서 `domestic`이 오늘 기관 순매수 상위 종목을 조회하고 그중 최근 1주일 수익률 1~3위를 선정 → `SendMessage(to="main", ...)`로 전달 → 오케스트레이터가 전체 리포트보다 먼저 "기관이 순매수 중이고 최근 1주 수익률이 가장 높은 3개 기업: ..."을 사용자에게 즉시 안내 → 이후 전체 분석 리포트를 이어서 전달.

**팀 협업 흐름**: `overseas`가 미국 반도체 지수 급락 신호를 발견 → `SendMessage(to="domestic", ...)`로 공유 → `domestic`이 국내 반도체 관련 종목 후보 판단에 반영하고 출력 파일에 반영 사유 기록 → 두 파일 모두에 해당 맥락이 일관되게 남음.

**에러 흐름**: 해외 분석 에이전트가 웹 조회 실패로 재시도 후에도 실패 → 오케스트레이터가 `reportwriter`에게 해외 제외 지시 → 국내 분석만으로 리포트 작성, "해외 주식 분석은 데이터 조회 실패로 이번 리포트에서 제외되었습니다" 명시 후 전달.

**재실행 흐름**: "국내 종목만 다시 분석해줘" → Phase 0에서 오늘자 `_workspace` 파일 존재 확인 → `domestic`만 재소환, 해외는 기존 파일 재사용 → `domestic`이 완료 알림을 `reportwriter`에게 보내면 리포트 재작성.
