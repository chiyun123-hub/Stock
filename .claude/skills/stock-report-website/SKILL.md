# 주식 리포트 웹사이트 발행

## 목적

채팅 텍스트로 붙여넣던 최종 리포트를, 날짜별 이력이 쌓이는 하나의 웹페이지로 대체한다. 사용자는 채팅 스크롤을 뒤지지 않고 링크 하나로 오늘 핵심 이슈와 과거 예측 이력을 확인한다.

## 데이터 소스 (단일 진실 공급원)

`site/data.json` — 날짜별 리포트를 누적 저장하는 배열. 없으면 `[]`로 새로 만든다. 최신 날짜가 배열 맨 앞에 오도록 정렬한다.

각 항목 스키마:

```json
{
  "date": "2026-08-12",
  "topIssues": [
    {"text": "... (최대 10개, 사실+숫자 중심 한 줄)", "sourceUrl": "https://...", "sourceTitle": "기사/공시 제목"}
  ],
  "up": [{"name": "...", "ticker": "...", "market": "KOSPI|KOSDAQ|US", "reason": "...",
          "sourceUrl": "https://...", "sourceTitle": "...",
          "priceAtPrediction": 36500, "priceAtPredictionTime": "2026-08-12 10:05 KST",
          "closePrice": null, "changePct": null, "hit": null,
          "settlementExcluded": false, "settlementNote": null,
          "targetPrice": 42000, "targetBasis": "증권사 컨센서스 목표주가(NH투자, 8/12 발표)"}],
  "down": [{"...동일 구조..."}],
  "institutionalTop3": [{"name": "...", "netBuy": "...", "weekReturn": "...", "note": "..."}],
  "disclaimer": "투자 자문이 아닌 참고용 스크리닝입니다.",
  "verified": {"domestic": false, "overseas": false},
  "accuracy": {"up": null, "down": null, "overall": null}
}
```

- `sourceUrl`/`sourceTitle`: 그 이슈·종목 판단의 근거가 된 실제 기사·공시·리포트의 원문 링크와 제목. `domestic`/`overseas`가 WebSearch/WebFetch나 뉴스 검색 스킬로 확인한 구체적 URL을 반드시 함께 기록한다 — 사이트에서 사용자가 이슈를 클릭해 원문으로 들어갈 수 있게 하기 위함이다. 여러 출처를 종합했으면 가장 핵심적인 것 하나만 링크해도 된다. 확보하지 못했으면 필드를 생략한다(문자열만 있던 과거 데이터와도 호환 — `topIssues` 항목이 문자열이면 `text`로 취급하고 링크 없이 렌더링).
- `priceAtPrediction`/`priceAtPredictionTime`: 분석 시점 기준가(현재가)와 그 가격을 확인한 시각. `domestic`/`overseas`가 종목을 후보로 낼 때 반드시 함께 기록한다(기준가는 정산의 기준선, 시각은 "이 가격이 언제 기준인지"를 사용자에게 보여주기 위함). 시각은 "YYYY-MM-DD HH:MM KST" 형식(해외는 "미국 정규장 종가 기준 YYYY-MM-DD"처럼 종가 기준이면 시각 대신 그렇게 표기해도 된다). 같은 배치에서 여러 종목을 같은 시각에 확인했으면 동일한 값을 반복해도 된다 — 지어내지 말고 실제 조회/서술 시점을 쓴다.
- `targetPrice`/`targetBasis`: "지금 얼마인데 얼마까지 오를/떨어질 것으로 보는지"를 보여주기 위한 목표가·예상가. 우선순위는 (1) 실제 증권사 목표주가(컨센서스나 최근 리포트 하나)를 확보했으면 그 값과 발행사·시점을 `targetBasis`에 남긴다, (2) 해외처럼 목표주가를 못 구했으면 최근 지지/저항선, 애널리스트 밴드, 또는 최근 유사 이벤트의 변동폭을 근거로 한 **추정 범위**를 만들고 `targetBasis`에 "추정(근거: ...)"라고 반드시 명시해 컨센서스와 구분한다, (3) 그마저 근거가 없으면 지어내지 말고 `targetPrice`를 생략한다. 범위로만 말할 수 있으면 `targetPrice`를 `"165,000~172,000"`처럼 문자열로 적어도 된다. "매수·매도 목표"가 아니라 "관측된 목표주가/예상 범위"라는 참고용 정보라는 어조를 유지한다.
- `closePrice`/`changePct`/`hit`은 정산 전에는 `null`이다. 정산 후 `domestic`/`overseas`가 채운다 — `hit`은 상승 예측인데 종가가 기준가보다 올랐거나 하락 예측인데 종가가 내렸으면 `true`, 반대면 `false`.
- `settlementExcluded`/`settlementNote`: 기준가를 신뢰할 수 없는 특수한 사정(예: 장 마감 후 촉매로 예측 직전에 이미 급등해서 기준가 자체가 왜곡되는 경우)이 있으면 `true`와 사유를 남기고, `hit`은 영구적으로 `null`로 둔다 — 억지로 왜곡된 숫자를 정산에 넣지 않는다. 사이트는 이 필드가 있으면 정산 차트에서 해당 종목을 "정산 제외"로 표시하고, `accuracy` 계산의 분모에서도 뺀다.
- `verified.domestic`/`verified.overseas`는 각 시장의 정산이 끝났는지 표시한다. 국내 정산은 국내 장 마감(15:30 KST) 후, 해외 정산은 미국 장 마감 후 각각 독립적으로 이뤄지므로 시점이 다를 수 있다.
- `accuracy`는 정산된 종목들만 집계한 적중률(%)이다. 두 시장이 모두 정산되기 전에는 정산된 쪽만으로 계산하고, 그 사실을 사이트에 표시한다.

오늘 날짜 항목이 이미 있으면(재실행) 상승/하락 후보 등 예측 내용은 덮어쓰지 않고 병합한다(이미 있는 `priceAtPrediction`은 유지). **정산 이후에는 예측 내용을 절대 사후 수정하지 않는다** — 그날 실제로 예측했던 내용 그대로 남겨야 예측 정확도를 나중에 검증할 수 있다.

## 발행 절차

1. `site/data.json`을 읽고 오늘 항목을 추가/갱신한다.
2. **Artifact를 쓰기 전 반드시 `artifact-design` 스킬을 먼저 로드**해 디자인 기준을 확인한다.
3. `site/index.html`을 새로 작성한다. `site/data.json` 전체 내용을 `<script type="application/json" id="report-data">`로 파일 안에 그대로 임베드한다 — Artifact는 단일 파일만 서빙하므로 외부 fetch가 불가능하다. 렌더링은 그 안에 포함된 JS로 클라이언트에서 처리한다(아래 "사이트 구성", "디자인 원칙" 참조).
4. `site/artifact_url.txt`가 있으면 그 URL을 읽어 `Artifact(file_path="site/index.html", url=기존URL, favicon="📉", ...)`로 같은 페이지에 갱신 발행한다. 없으면(최초 발행) `url` 없이 발행하고, 반환된 URL을 `site/artifact_url.txt`에 저장한다.
5. 사용자에게는 리포트 본문을 채팅에 붙여넣지 않는다. 발행된 링크와 오늘 핵심 이슈 1~2개만 짧게 언급하고 나머지는 사이트에서 보라고 안내한다.

## 사이트 구성 — 사이드바 앱 셸 (스크롤 탐색 금지)

**스크롤을 내려서 콘텐츠를 찾는 구조를 쓰지 않는다.** 왼쪽 고정 사이드바에서 클릭으로 화면을 전환하는 앱 셸 구조를 쓴다(`grid-template-columns: 264px 1fr`, 좁은 화면에서는 사이드바가 상단으로 접힘). 사이드바 구성:

1. **오늘의 핵심 이슈** (최상단, 단일 항목, 기본 선택) — 오늘 핵심 이슈 10가지를 사실+숫자 중심 한 줄로 나열 (예: "한화솔루션, 기관 5거래일 연속 순매수·1주 +35%"). `up`/`down`/`institutionalTop3`의 근거를 압축해서 만든다. **`sourceUrl`이 있는 이슈는 클릭 가능한 항목으로 만들어, 클릭하면 분석에 사용한 원문 기사/공시가 새 탭으로 열리게 한다**(`target="_blank" rel="noopener noreferrer"`). 클릭 가능함을 시각적으로 드러낸다(외부 링크 화살표 `↗` 등, hover 시 밑줄/색 변화). 링크가 없는 이슈는 클릭 불가능한 일반 텍스트로 둔다 — 없는 링크를 지어내지 않는다. 같은 방식으로 "날짜별 예측 이력" 화면의 종목별 근거에도 `sourceUrl`이 있으면 원문 링크를 붙인다.
2. **날짜별 예측 이력** (그룹, 날짜 목록) — 각 날짜를 누르면 그날의 상승/하락 후보(종목·근거 1줄·기준가)와 기관 순매수 Top3를 메인 영역에 보여준다. 종목마다 **"현재 {priceAtPrediction} → 목표 {targetPrice}"**를 근거 아래 별도 줄로 표시한다(상승 후보는 위쪽 화살표/붉은 톤, 하락 후보는 아래쪽 화살표/파란 톤 느낌으로 방향을 암시하되 화려한 아이콘은 쓰지 않는다). `targetBasis`가 "추정"으로 시작하면 옅은 색으로 "(추정)"을 병기해 실제 컨센서스와 구분한다. `targetPrice`가 없는 종목은 이 줄 자체를 생략한다(빈 값 표시 금지).
3. **날짜별 예측 정확도** (그룹, 날짜 목록) — 각 날짜 옆에 적중률 배지(미정산이면 "정산 전"). 누르면 정산 차트 화면으로 전환한다.

메인 영역은 클릭한 항목에 해당하는 섹션 하나만 보여주고 나머지는 `hidden`으로 감춘다(전부 한 페이지에 이어 붙여서 스크롤로 찾게 하지 않는다). 섹션 전환 시 짧은 fade+slide(`translateY(6px)` → `0`, 200ms 안쪽) 애니메이션을 준다. 사이드바 항목은 hover/active 시 배경색 전환 + 좌측 강조 바(accent bar)가 `scaleY`로 나타나는 전환을 준다. 이슈 리스트 각 줄은 순차적으로 약간의 지연(stagger)을 두고 떠오르게 한다. 정산 차트의 막대는 `scaleX` 애니메이션으로 자라난다. **`prefers-reduced-motion: reduce`에서는 모든 애니메이션을 끈다.**

- **정산 차트 화면**: 정산된 종목(`hit`이 `null`이 아닌 것)이 하나라도 있으면 종목별 등락률 막대를 그린다.
  - 순수 CSS/DOM으로 그린다(외부 차트 라이브러리 금지, self-contained 원칙). 막대 하나 = 종목 하나, 0% 기준선에서 좌우로 자라난다.
  - 색은 예측 방향이 아니라 **적중 여부**로 칠한다: 적중은 밝은 톤, 실패는 어둡게 죽인 톤 — 상승/하락 표기는 라벨 텍스트("상승예측"/"하락예측")로 병기한다.
  - 화면 상단에 전체 적중률(`accuracy.overall` 또는 직접 계산)과 상승/하락 각각의 적중률을 숫자로 크게 표시한다.
  - 정산 전 날짜는 "아직 정산 전입니다" 안내만 보여주고 빈 차트를 그리지 않는다.
  - 미정산 개별 종목은 "정산 대기"로 표기한다.
- 문장은 짧게, 종목당 근거 1줄, 숫자 위주. 면책 문구(`disclaimer`)는 각 날짜 화면 상단에 작게 표시한다.
- 참고 구현: `site/index.html`(사이드바 앱 셸 + 애니메이션 반영된 최신 버전)을 그대로 템플릿으로 삼아, 데이터만 갈아 끼우고 구조는 유지한다.

## 디자인 원칙 (차가운 분위기)

- **배경**: 짙은 차콜/청회색 계열(#0a0c0e~#14171a). 순검정은 피한다(너무 하드함).
- **타이포**: 시스템 산세리프 또는 모노스페이스, 자간은 약간 넓게, 볼드는 제목 등 최소한만 사용. 장식적 폰트 금지.
- **색**: 기본은 회색조. 포인트 색은 한국 증시 관례를 따라 상승=채도 낮춘 붉은 계열(예: #c65a5a), 하락=채도 낮춘 청색 계열(예: #5a84c6) 두 가지만 쓴다. 그 외 색상은 쓰지 않는다.
- **레이아웃**: 각진 모서리(둥근 카드 금지 또는 아주 미세한 radius만), 얇은 1px 구분선, 그림자는 최소화하거나 없앤다. 여백을 넉넉히 둬 건조하고 정제된 인상을 유지한다.
- **애니메이션**: 없거나 아주 짧은 fade 정도만. 통통 튀는 트랜지션 금지.
- 이 페이지는 "차가운 분위기"가 사용자의 명시적 요구이므로, 라이트/다크 시스템 설정과 무관하게 다크(차가운) 테마로 고정해도 된다. 다만 `artifact-design` 스킬의 구조적 기본기(반응형, 접근성, 자체완결형 CSS 등)는 그대로 따른다.

## 에러 핸들링

- `site/data.json` 파싱 실패 시 `site/data.json.bak`으로 백업하고 빈 배열로 새로 시작하되, 사용자에게 데이터 유실 가능성을 알린다.
- Artifact 발행 실패 시 1회 재시도한다. 재실패하면 `site/index.html` 로컬 경로만 사용자에게 안내한다.
